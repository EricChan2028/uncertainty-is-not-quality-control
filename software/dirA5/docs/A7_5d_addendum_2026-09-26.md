# A7-5d addendum: blind re-audit of the R-Zero audit samples (registered 26 Sep 2026, before any of its data)

Why: the registered A7-5 audits (rz_audit200_wf.js, the frozen A3 workflow) were not blind to iteration. Each judge's fetch
command ran inside dirB/runs/rzero_qwen3_4b_Base_s<S>_it<i>, and item ids (rz<S>i<i>r<n>) encode seed and iteration. RZ-P1
(early-run HOLDS 2/2, ledger section 15) could therefore partly reflect judge expectation. A7b showed that blinding did not
change the drift in our own loops (+24.7 blind vs +23.0 original); this addendum runs the same test on the R-Zero samples.
It does not change RZ-P1 or RZ-P2, which stand as registered. Four rounds of two adversarial Opus reviewers shaped this
text and code (records in ext/a75d_reviews/).

## Sample (dirA5/code/a75d_sample.py)
All items of the six registered 200-item audit samples (R-Zero seeds 0 and 1, iterations 1, 2 and 3;
dirB/runs/rzero_qwen3_4b_Base_s<S>_it<i>/audit_admitted.json, each with its original non-blind verdict), 1,200 items,
shuffled together (random.Random(20260926 + 75)) and given neutral keys z0000..z1199 (key zNNNN is line NNNN + 1). The judges
see only key and problem text, one JSON object per line, in dirA5/results/a75d_blind/items.jsonl (path and name carry no run
information), fetched by line range. Problem text is written as UTF-8 (ensure_ascii=False), as the original judges saw it
(77 items contain Chinese text; their share rises with iteration). The key file lives in a separate directory
(dirA5/results/a75d_key/key_full.jsonl) that the judges are never pointed to. Right after the build, and before any
judging, the sha256 of items.jsonl and key_full.jsonl are appended to docs/registration_hashes.txt.

## Pre-launch scan
Immediately before pass 1, every local copy of R-Zero item-level data is removed from the launching machine, and the Temp
tree (<LOCAL_HOME>/AppData/Local/Temp) and the working directory are scanned (errors ignored) with grep -rlaE
'rz[01]i[1-3]r[0-9]' (must be empty) and for files holding 25 or more distinct z-keys (\bz[01][0-9]{3}\b; must be none apart
from this package). Both outputs are appended to registration_hashes.txt. Known exception: the .claude transcript tree
(which holds the original R-Zero judge transcripts) is outside the scan; it is guarded by the ".claude" ban and the
output-side test (3) below. (Round-3 review found simulated key files left in the
session scratchpad by earlier reviewers; they were deleted and the scan was clean at 07:51 26 Sep; the scan is repeated at
launch.)

## Judging (dirA5/code/a75d_blind_wf.js)
The frozen audit definitions, verbatim (SOLVABLE / UNSOLVABLE / AMBIGUOUS, "Be strict: a default assumption you would have to
invent makes it UNSOLVABLE", confidence, note <= 20 words, the same "written by a Qwen3-4B-Base language model and ADMITTED by
a self-play filter" sentence for all items), 25 consecutive lines per judge (48 Opus judges), verdicts returned through a
structured schema whose keys are restricted to the judge's own 25 keys; each returned verdict is tagged with its judge's line
range. The operational lines differ from the original audit: judges are told not to read any other part of the file or any
other file of this project, not to modify the server, and that they may check computations with local code in a temporary
directory (not on the server). Pass 1 (args {pass: 1}) runs exactly once over lines 1-1200; its `verdicts` array is saved
unedited, as a bare list, as dirA5/results/a75d_blind/blind_verdicts.json (the read verifies each passed batch against the
judges' recorded structured returns). The judges run as Opus workflow subagents with effort 'xhigh' set in the workflow; the
original R-Zero audits and A7b ran at model claude-opus-5-5 with effort xhigh, and a judge that ran at any other setting
fails the blindness check. No judge is skipped by hand; any skip is reported. A user message relayed to the judges is
recorded verbatim in the check file; if it mentions the items, R-Zero, iterations or the hypothesis, that is reported as a
deviation. Until the read is done, no R-Zero item-level observation or drift number is added to the project memory index
that judges inherit. Before hashing, a 2-judge pilot of copies of the workflow and checker pointed at a dummy items file (no
R-Zero content) was run to test the chain on real transcripts.

## Blindness check (dirA5/code/a75d_blind_check.py; run locally right after each pass)
`python3 a75d_blind_check.py <out.json> all|<ranges json> <transcript dir> [<dir> ...]`. Every workflow subagent in the
directories must be a judge "judge:<a>-<b>" with exactly one computed-task line containing the registered fetch command for
exactly that range (the port is read from it, must be <HOST> or <HOST> - both mount the same volume - and must agree within
the pass), else the check aborts. A transcript with no structured return and
no failing call is neutral (an interrupted attempt) and is ignored. Every other transcript passes only if (1) it made a FETCH
- the registered command for its own range, or a sed re-read of a sub-range of its own lines in the same form, through the
Bash tool - whose result is not an error and contains all 25 of its keys; (2) every other call is allowed: StructuredOutput,
TodoWrite; Write / Edit / Read of a file under a temp directory (no ".."); a Bash / PowerShell command that names no
transcript, task-output, key, audit or item file of this project, kills no processes (taskkill, pkill, killall, kill,
Stop-Process), and - outside temp-directory paths - uses no network tool, no server address and no user or home directory
(Windows or Git-Bash form; no "..", "~", bare "cd"); (3) no result of a
non-fetch call contains key or audit information (rzero, rz<S>i<i>r<n> ids, orig_verdict, audit_admitted, key_full,
"iteration": n, "run": "..."); (4) every assistant turn (harness-inserted "<synthetic>" turns excepted) ran as
claude-opus-5-5 / xhigh. A batch passes if it has at least
one non-neutral transcript and all of them pass (harness retries and resumed attempts included); it is dropped otherwise, and
absent if it has no non-neutral transcript. Dropped and absent batches count as missing. Calibration on the 49 original
R-Zero judge sessions (tool calls only, not verdicts): 39 computed locally; the rule allows 66 of 67 local computation calls,
and 47 of 49 sessions would pass (one read a background-task output file, one computed on the server over ssh). The check
file lists every non-fetch call, the relayed user text, the structured returns' hashes, the number of judge sessions with at
least one allowed local computation call (reported against 39 of 49 originally), models, efforts and harness versions.
Known limits: the rule filters command text, so a read of a non-project local file by a relative path would pass, and a
derived mapping in a format other than those in (3) would not be caught by (3); the pre-launch scan and the output-side test
are the guards against seeing item-level run information. Some harmless code is also rejected (e.g. sympy's curl() called
in command position, a variable named cd used alone); a rejected batch is re-judged.

## Merge rule and passes (dirA5/code/a75d_read.py)
A verdict is valid if its label is SOLVABLE / UNSOLVABLE / AMBIGUOUS after strip().upper(), its key is one of the 1,200 keys,
the key's line lies in the verdict's tagged range, and that batch passed the blindness check. A key takes the label of the
first pass in which all its valid verdicts agree; otherwise it is missing. After a pass with missing keys the read outputs
only counts and the next pass's ranges - the whole 25-line batches that hold a missing key - never outcome statistics. The
next pass is then mandatory: pass 2 (args {pass: 2, ranges}) and, if keys are still missing, pass 3, each a fresh launch,
saved unedited as blind_verdicts_rejudge.json / blind_verdicts_rejudge2.json and checked the same way
(blindness_check_rejudge.json / blindness_check_rejudge2.json). A later pass only fills keys that are still missing; earlier
labels are never replaced. If any key is missing after pass 3, RB-P1..RB-P3 are NOT RUN. An interrupted pass is resumed
with resumeFromRunId (never restarted) and checked over every directory of its resume chain. For each pass, the workflow run
id(s) and the sha256 of its verdict file and check file are appended to registration_hashes.txt in one entry before the read
is run; the transcript directories are kept. The read aborts on a verdict file without its check file, a check whose batches
differ from the registered ones, a verdict tagged with a batch its check never saw, saved verdicts of a passed batch that
differ from every structured return of its judges, passes sharing a transcript directory, a port outside {<HOST>, <HOST>}, or
a pass present while an earlier one is missing or not needed. Any abort of the checker or the read means NOT RUN, reported
with its reason; hashed code is never edited after its data exist.
Ill-posed = UNSOLVABLE or AMBIGUOUS. The read also recomputes every original verdict from audit_admitted.json and requires
item-by-item agreement with key_full.jsonl, and the per-seed original drift must equal the registered RZ-P1 audits (+23.0
/ +27.0 points; pooled +25.0) (else NOT RUN). The six audit_admitted.json files are hashed with this addendum.

## Predictions (confirmatory)
- RB-P1 (the drift survives blinding): blind ill-posed share at it3 >= blind share at it1 + 10 points in BOTH seeds (2/2).
- RB-P2 (no iteration-dependent shift from the non-blind conditions): pooled over the 2 seeds, |D_blind - D_orig| <= 7.5
  points, where D = share(it3) - share(it1) on the same items (pooled = the 400 items of the iteration across seeds).
- RB-P3 (item agreement): binary (ill-posed vs solvable) Cohen's kappa between blind and original verdicts over all 1,200
  items >= 0.60.
What RB-P2 tests: the combined effect of every way the original judging differed from the blind one - knowledge of run name
and ids; batches of a single run vs mixed batches; raw text vs JSON lines (newlines shown as \n, LaTeX backslashes doubled;
the A7b format); a file push vs a structured return; the operational prompt lines (above); judging it1 and it3 about a day
apart vs together, with a different memory index and harness version (2.1.281 for the original it1/it2 audits, 2.1.282 for
it3) and, for the original it1 judges only, a relayed user request - not expectation alone. Local computation is available
in both. Descriptive splits of D_blind - D_orig within multi-line vs single-line items and CJK vs non-CJK items (both mixes
shift with iteration) are reported.
Descriptive: shares per seed x iteration (blind and original), it2, three-class kappa, per-seed D_blind and D_orig, a paired
item bootstrap (4,000 replicates, seed 20260926, items resampled within seed x iteration, the same draw for blind and
original) with 95% CIs for D_blind and D_blind - D_orig, counts per pass, blind label consistency across the 6 problem texts
that occur more than once (14 items), and judge sessions with local computation.

## Headline rule and consequences (fixed now)
If RB-P2 holds, the paper's number for the R-Zero drift is the registered original audit (+23.0 / +27.0, pooled +25.0), with
the blind estimate and its CI as robustness; if RB-P2 fails in either direction, the headline is the source with the smaller
POOLED drift (quoted with that source's per-seed values), with both shown side by side; if RB-P2 is NOT RUN, the headline
stays the registered original audit, with the NOT RUN and its counts stated.
- RB-P1 fails in one seed: the blind drift is shown at the 10-point threshold in one seed only; the paper says so and gives
  both blind per-seed numbers.
- RB-P1 fails in both seeds: the R-Zero drift is not established under blind judging at the registered threshold; the paper
  states that and keeps RZ-P1 only as the registered non-blind result.
- RB-P2 fails with D_blind < D_orig - 7.5: the audited R-Zero drift is reported as inflated by the non-blind conditions.
  With D_blind > D_orig + 7.5, the original audit understated it (no downside for the drift claim; the headline rule
  applies).
- RB-P3 fails: item-level verdicts on R-Zero items are not reliable across judge runs, and only aggregate shares are
  interpreted.
- NOT RUN (keys still missing after pass 3, or the original verdicts do not reproduce): reported with the counts, and no RB
  verdict is given.
