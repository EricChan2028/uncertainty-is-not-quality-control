# A12 amendment 2 (26 Sep 2026, after pass 2 of part 1, before pass 3)

**What changes.** Pass 3 of part 1 is checked with `a12_blind_check_am2.py`. `make_am2.py` builds it from the amendment-1
checker (sha256 8621965a...). The new checker treats a judge's own background tasks as local computation. A task id counts as
the judge's own when the result of one of that judge's earlier tool calls, in the same transcript, announces it with
"Command running in background with ID: <id>" or "... was moved to the background (ID: <id>)". Only for such ids:
- TaskStop of the id is allowed.
- A Read of `<temp dir>/.../tasks/<id>.output`, or a Bash, PowerShell or Monitor command that names that path, is judged
  with the path rewritten to `.../judgetmp/<id>.output`. Every other rule still applies to the rest of the command.
- ToolSearch with a query `select:` naming only TaskStop and/or Monitor is allowed. Such a query only loads those tools'
  definitions.

Monitor commands are judged like Bash commands. All other rules are unchanged, including the ban on reading any other file
under `tasks/`, the leak patterns (applied to the result of every non-fetch call, including these), the fetch and model
checks, and the framing check. The output adds `"amendment": "A12-am1+am2 (a12_blind_check_am2.py)"`.

**Why.** Pass 2 dropped 2 of 14 batches, [26,50] and [876,900]. Both batches had also been dropped in pass 1 for the same
reason:
- The judge had started a long local computation, the harness moved it to the background, and the judge then stopped it
  (TaskStop) or read its output file (`tasks/<id>.output`).
- The registration allows local computation (section 1.4 (2)). The ban on `tasks/` is there so that judges cannot read other
  tasks' outputs; a judge's own background computation is not such a case.
- Pass 3 is the last pass. If either batch were dropped again, part 1 would be NOT RUN.

A diagnostic run of the amended checker, whose outputs were deleted and are not used, shows:
- on the pass-2 transcripts, both batches pass;
- on the pass-1 transcripts, three batches still fail. Their reasons fall outside this amendment: another banned command
  form, pkill/taskkill, and a TaskStop of an id never announced to the judge.

**What does not change.**
- Passes 1 and 2 keep their checks (hash entries 20:42:23 and 20:50:42).
- The workflow, the items, the pass-3 batches (the 2 printed by the read after pass 2), the merge rule, the read and every
  pre-stated reading are unchanged.
- The amendment is made before any pass-3 transcript exists. It uses no verdict or statistic, only the checkers' bad-call
  lists.
- It is reported as a deviation, together with amendment 1.
