# A12 amendment 1 (26 Sep 2026, after pass 1 of part 1, before pass 2)

**What changes.** Passes 2 and 3 of part 1 are checked with `a12_blind_check_am1.py` instead of `a12_blind_check.py`. The
amended checker is the registered one with a single change, and it is built by `make_am1.py` from the registered file
(sha256 9f0b1eb0...).

Before the banned-name rule (`BAD_ANY`) is applied to a Write/Edit/Read path or to a Bash/PowerShell command, the checker
renames one kind of folder to `judgetmp`: a judge's own temporary subfolder whose name starts with `a12`, located directly
under a scratchpad, temp or tmp directory. The project directory names `a12_key`, `a12_blind`, `a12_open`, `a12_runs`,
`a12_draft` and `a12_pilot` are not renamed.

Nothing else changes:
- all other banned names;
- the bans on `.claude`, `tasks/`, `subagents/` and `journal.jsonl`;
- the network, home-directory, `..` and kill rules;
- the leak patterns;
- the fetch and model checks;
- the framing check.

The output file keeps the registered format and adds the field `"amendment": "A12-am1 (a12_blind_check_am1.py)"`.

**Why.** In pass 1, 14 of 48 batches were dropped by the check.
- In 8 of them, the only failing calls were local computations in a temporary folder that the judge had named after the
  items file's directory (`a12_blind`), for example `scratchpad/a12` or `scratchpad/a12b`. Such folders exist only on the
  launching machine and hold only the judge's own scripts. This count comes from a diagnostic run of the amended checker on
  the pass-1 transcripts; its output was deleted and is not used.
- The banned name `a12` was added to the checker so that judges could not read A12 key or result files. The registration
  allows local computation in a temporary directory (section 1.4 (2)).
- The other 6 dropped batches read a background task's output under `tasks/`, used TaskStop, Monitor or ToolSearch, ran
  pkill/taskkill, or used another banned command form. These stay banned.
- At the pass-1 drop rate, some of the 14 batches would probably still be dropped after pass 3, and part 1 would then be
  NOT RUN because keys are missing.

**What does not change.**
- Pass 1 keeps its registered check: 34 passed, 14 dropped. Its hash entry of 2026-09-26 20:42:23 stands, and the amended
  checker is not applied to pass 1.
- The workflow, the items, the batches (the 14 printed by the read after pass 1), the merge rule, the read and every
  pre-stated reading are unchanged.
- The amendment is made before any pass-2 transcript exists. It uses no verdict or statistic of pass 1; only the checker's
  bad-call lists were inspected.
- It is reported as a deviation.

**Housekeeping before pass 2.**
- The judges' pass-1 temporary folders, and every other file in the launching machine's scratchpad except the checker, the
  workflow and the saved pass-1 files, were deleted.
- The pass-1 workflow output was deleted from the local task directory after its verdicts were saved to the server.

**Correction.** The checker hashed at 2026-09-26 20:43:42 (sha256 f12113b9...) crashed on every command, because its helper
function `neutral` was shadowed by a variable of the same name in the registered code. That version, and this note's first
version (which gave 11 instead of 8), were superseded before any pass-2 transcript existed. The helper is now
`am1_rename`; nothing else changed.
